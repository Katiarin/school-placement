# Оценка вариантов размещения школ — Фрунзенский район

Отдельное веб-приложение для оценки обеспеченности населения местами в общеобразовательных
организациях при размещении новых школ в кварталах. Расчёт полностью воспроизводит метод
практики 2 и работает на сохранённых данных — данные города заново не скачиваются.

Приложение открывается в браузере, интерфейс и сообщения — на русском языке. Платные сервисы и
обращения к языковой модели не используются.

---

## Быстрый запуск (Windows)

```bat
cd C:\Users\Катя\Documents\school-placement
setup.bat
run.bat
```

`setup.bat` создаёт окружение `.venv`, устанавливает зависимости и один раз готовит данные из
проекта практики 2. `run.bat` запускает сервер и открывает <http://127.0.0.1:8000/>.

При первом запуске `setup.bat` ищет исходный проект в `..\frunzenskiy-ai` (то есть
`C:\Users\Катя\Documents\frunzenskiy-ai`). Если проект лежит в другом месте:

```bat
setup.bat --source "D:\путь\к\frunzenskiy-ai"
```

### Запуск вручную

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts\prepare_data.py --source "C:\Users\Катя\Documents\frunzenskiy-ai"
.venv\Scripts\python.exe app.py
```

Параметры `app.py`: `--host`, `--port` (по умолчанию 8000), `--data` (папка подготовленных
данных), `--no-browser`.

Остановка сервера — `Ctrl+C`.

Если в интерфейсе появилось сообщение **«Нет связи с сервером»** или `Failed to fetch`,
значит окно с `run.bat` закрыто или сервер остановлен. Запустите `run.bat` снова и обновите
страницу. Окно консоли нужно оставлять открытым (можно свернуть) — при его закрытии
останавливается и сервер.

## Как устроена работа

### Данные

Приложение читает из проекта практики 2 **только на чтение**:

| Файл | Что используется |
|---|---|
| `outputs/frunzensky_indicators.csv` | идентификаторы кварталов, население, вместимость школ, сохранённая обеспеченность |
| `outputs/frunzensky_blocks.geojson` | геометрия кварталов |
| `outputs/accessibility_matrix_drive.parquet` | матрица времени в пути между кварталами, минуты |

`scripts/prepare_data.py` проверяет целостность (совпадение кварталов и матрицы, порядок строк),
упрощает геометрию и складывает всё в `data/`:

```
data/blocks.csv                  атрибуты кварталов + сохранённая обеспеченность
data/blocks.geojson              геометрия для карты (WGS84/EPSG:4326, упрощение 0.5 м)
data/accessibility_matrix.npz    подматрица 208×208 (float32)
data/meta.json                   параметры, источники, контрольные суммы, результат сверки
```

После этого приложение работает с `data/` и не обращается к проекту практики 2. Интернет нужен
только для подложки OpenStreetMap; без него кварталы и результаты расчёта остаются на карте,
но без подписей улиц.

### Метод расчёта

Используется `blocksnet.analysis.provision.competitive_provision` из **BlocksNet 1.0.0a9** —
та же функция и те же параметры, что в ноутбуке практики 2:

1. потребность квартала = `ceil(население / 1000 × 120)` мест (норматив 120 мест на 1000 жителей);
2. собственная вместимость квартала закрывает его потребность;
3. оставшийся спрос распределяется линейной оптимизацией между школами в пределах **15 минут**
   (матрица времени в пути на автомобиле);
4. обеспеченность квартала = закрытая в нормативе потребность / потребность;
5. **дефицит мест** = потребность − закрытая в нормативе потребность (суммарно по территории).

Новая школа увеличивает вместимость своего квартала. Население, матрица времени в пути и
нормативы не меняются.

### Проверка воспроизведения

При подготовке данных и при каждом запуске приложение пересчитывает исходное состояние
(без новых школ) и сравнивает его с `provision_school` из практики 2:

```
Сверка с практикой 2: OK (макс. отклонение 1.11e-16)
```

Исходные показатели территории: 208 кварталов (из них 117 с населением), население 399 750 чел.,
вместимость школ 24 722 места, потребность 48 033 места, дефицит 23 311 мест, обеспеченность 51,5 %.

## Интерфейс

### Карта

Три режима:

- **Исходное состояние** — обеспеченность по кварталам, % (серая заливка — нет населения);
- **Сценарий** — обеспеченность после добавления школ;
- **Изменение** — разница со исходным состоянием: Δ обеспеченности (п.п.) или Δ дефицита (мест).

Клик по кварталу открывает карточку: население, потребность, вместимость школ, обеспеченность и
дефицит (в режиме сценария — в формате «база → сценарий»).

### Свои варианты размещения

1. Выберите квартал на карте или в списке.
2. Укажите вместимость в местах (только целое положительное число).
3. «Добавить» — школа попадает в сценарий; можно добавить несколько школ в разные кварталы.
4. «Рассчитать сценарий» — пересчёт по всей территории, показатели сравниваются с исходными.
5. «Сбросить» — возврат к исходному состоянию.
6. «Экспорт CSV» — таблица результатов по кварталам (разделитель `;`, UTF-8 с BOM — открывается
   в Excel, десятичный разделитель — запятая).

### Автоматический подбор квартала

Поле «Вместимость новой школы, мест» (по умолчанию 600) и кнопка «Разместить автоматически».
Алгоритм:

1. берутся исходные данные о населении и существующих школах, независимо от текущего сценария;
2. по очереди проверяется **каждый квартал территории** (в текущих данных — 208): в модель
   добавляется одна школа заданной вместимости, выполняется полный пересчёт территории;
3. каждый вариант считается независимо — вместимость не накапливается между проверками; строки
   результата — это отдельные варианты, а не одновременное размещение школ во всех кварталах;
4. для каждого варианта вычисляется суммарный дефицит и его сокращение относительно исходного
   состояния, а также дефицит мест в самом квартале до и после сценария;
5. рекомендация выбирается среди кварталов, где школа действительно нужна: есть население и
   дефицит мест (в текущих данных — 111 из 208);
6. сначала максимизируется сокращение дефицита по району; если оно одинаково, приоритет отдаётся
   кварталу с **наибольшим дефицитом мест в самом квартале**. Если и этот показатель совпадает,
   показываются все такие кварталы.

В таблице автоматического подбора есть отдельные столбцы «Дефицит квартала до» и «Дефицит квартала
после»; кроме того, показан дефицит по району после варианта. По умолчанию включён фильтр «Только
кварталы, где нужна школа»: видны 111 кварталов с населением и дефицитом. Снимите фильтр, чтобы
увидеть все 208 проверенных вариантов; кварталы без населения или без дефицита помечены как
нерекомендуемые. Знаком ★ отмечен рекомендованный квартал.

Во время перебора отображаются прогресс-бар, число проверенных кварталов и текущий лучший
результат. Ошибки отдельных кварталов показываются явно; при неполном переборе приложение прямо
сообщает, что лучший вариант найден только среди проверенных.

После завершения рекомендованный квартал подсвечивается на карте и открывается его карточка, но
школа автоматически не добавляется. Нажмите на строку таблицы, чтобы рассчитать вариант с одной
школой в этом квартале.

Перебор занимает около 50–60 секунд (208 задач оптимизации).

> В текущих данных вся территория района находится в пределах 15 минут доступности, а
> вместимость новой школы (600 мест) меньше остаточного дефицита (23 311 мест). Поэтому все
> 208 кварталов дают одинаковое сокращение дефицита по району — 600 мест. Чтобы не предлагать школу
> сразу во всех кварталах, рекомендация выбирается только среди 111 кварталов с населением и
> дефицитом, а при равенстве — по наибольшему дефициту мест: в текущих данных это квартал 6887
> (1098 мест до сценария, 498 после). Кварталы без населения (91) и без дефицита (6) проверяются,
> но не рекомендуются.

### Сравнение вариантов

- одна школа 600 мест в выбранном квартале;
- две школы по 300 мест в двух выбранных кварталах;
- одна школа 600 мест в квартале, найденном автоматически.

Можно сравнивать два или три варианта: в ненужном варианте выберите в списке кварталов
«— не сравнивать». Прочерк в любом из двух кварталов варианта 2 отключает весь вариант.
Кнопка «Сравнить два/три варианта» строит сравнительную таблицу: добавленная вместимость,
дефицит и обеспеченность района до и после, сокращение дефицита. Под итоговой строкой каждого
сценария показан локальный эффект в кварталах размещения: дефицит и обеспеченность до → после,
число затронутых кварталов и население. Для двух школ локальные показатели раскрываются по каждому
кварталу. Это важно, когда у вариантов одинаковая вместимость и одинаковое сокращение дефицита по
району: локальные значения показывают, где именно школа закрывает потребность. Лучший вариант по
сокращению дефицита отмечается ★; при равенстве нужно смотреть локальные показатели.

### Эксперимент по практике 3

В блоке «Сравнение вариантов» предусмотрены три сценария:

- **А** — одна школа 600 мест в выбранном квартале;
- **Б** — две школы по 300 мест в двух выбранных кварталах;
- **В** — одна школа 600 мест в квартале, найденном автоматически.

До запуска автоподбора выберите кварталы для А и Б и кратко зафиксируйте обоснование своего выбора
(например, в отчёте или рядом с сохранённым сценарием). Затем сравните А, Б и В по добавленной
вместимости, остаточному дефициту, сокращению дефицита и обеспеченности. Для ответов на вопросы
практики используйте таблицу сравнения, карту изменений и таблицу по кварталам. Помните, что
автоподбор проверяет варианты с одной школой; вариант Б с двумя школами может дать другой результат.

### Сохранённые сценарии

Сценарии сохраняются в браузере (`localStorage`), их можно показать на карте, удалить и сравнить
между собой.

## Проверки

```bat
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют:

- исходный расчёт воспроизводит сохранённые результаты практики 2 (без новых школ);
- прирост вместимости сети учитывается ровно на вместимость школ;
- вместимость принимается только целым положительным числом (0, −1, 1.5, «abc», пустое
  значение, `true` — отклоняются);
- сценарии не изменяют исходные данные и матрицу;
- автоматический поиск проверяет все 208 кварталов независимо (вместимость не накапливается);
- кварталы без населения или без дефицита проверяются, но не рекомендуются;
- при равном сокращении по району рекомендуется квартал с наибольшим дефицитом мест;
- ручное размещение в найденном квартале воспроизводит автоматический результат;
- равноценные лучшие результаты обрабатываются корректно;
- неполный перебор помечается как неполный, ошибки кварталов возвращаются явно;
- API сценариев, сравнения и экспорта CSV работает согласованно.

Полный тест с перебором всех 208 кварталов помечен `slow` и занимает около минуты.

## Допущения и ограничения

- Численность населения, матрица времени в пути и нормативы одинаковы для всех вариантов.
- Новая школа учитывается только как вместимость квартала; площадь участка, этажность и стоимость
  не моделируются.
- Время в пути — на автомобиле; интермодальные и пешие поездки не учитываются.
- Распределение мест конкурентное: жители могут пользоваться школами соседних кварталов в
  пределах 15 минут.
- Подложка OpenStreetMap включается в карте и требует интернета; без неё карта и расчёты
  продолжают работать. Leaflet и все данные хранятся локально.
- Приложение сравнивает обеспеченность местами в школах для вариантов размещения по кварталам.
  **Оно не выбирает земельный участок и не оценивает возможность строительства** — для этого
  требуется отдельное градостроительное обоснование.
